# RoboMaster 自瞄视觉系统（仿真验证）

一个可完整跑通的 RoboMaster 自瞄视觉流水线：**图像与云台姿态时间对齐 → 装甲板检测 → PnP 位姿解算 → 卡尔曼滤波跟踪与预测 → 弹道解算与开火决策**。
上层的感知、跟踪与决策算法由我独立实现，运行在 Bevy 编写的仿真器上，通过 ROS2 收发图像、云台姿态、弹道速度和装甲板真值。

> 项目定位：湖南大学工程力学专业本科一年级，在跃鹿战队算法组自瞄培训中，从零完成的视觉算法实践。

## 一句话能力概览

| 环节 | 我做的事 | 关键做法 |
| --- | --- | --- |
| 数据流对齐 | 让每帧图像配到拍摄那一刻的云台姿态 | 时间戳最近邻匹配 + `steady_clock`/系统时钟映射 |
| 装甲板检测 | 灯条提取与装甲板配对 | HSV 颜色阈值、轮廓几何筛选、多特征加权评分 |
| 位姿解算 | 把像素角点还原成三维位置 | `solvePnP`（IPPE）+ 重投影误差自检 + 相机→云台→IMU 换算 |
| 目标跟踪 | 单目标位置 / 速度估计与预测 | 匀速模型卡尔曼滤波 + χ² 新息门控 + 关联选板 |
| 弹道解算 | 由目标位置算出云台角与开火时机 | 抛体弹道解析解 + 延迟补偿 + 开火门控 |

## 项目背景

RoboMaster 赛场上，视觉系统要在目标高速平移、装甲板频繁遮挡的情况下，把目标的三维位置、速度送到云台，并在弹丸飞行时间之前算好提前量。这条链路每一步的误差都会向后累积：

- **检测误差** → 角点不准 → PnP 位置偏差
- **位姿误差** → 跟踪输入噪声 → 速度估计不稳
- **速度误差** → 预测偏差 → 开火打偏

因此本项目不是四个孤立模块，而是围绕「**误差从哪里来、怎么量、怎么抑制**」串起来的一条链路。我在仿真器里给自己搭了「PnP 位姿 vs 真值」「t+250 ms 预测 vs 真值」两个可量化验收场景，每一处参数选择都有实测依据。

## 本人实现内容

### 1. 图像–姿态时间对齐（IO 层）

图像和姿态反馈来自两条独立话题，时间戳并不严格同步，直接用「最新一帧姿态」会让位置随云台转动而抖动。

- 维护最近 128 条姿态反馈的历史队列，按 `header.stamp` 为每张图像找**采样时间最接近**的一帧，而不是拿最新值。
- ROS `SystemTime` 与程序内部 `steady_clock` 做了映射：用两次采样中点估计系统时钟快照，把图像时间戳换算到单调时钟，避免系统时间跳变影响跟踪的 `dt`。
- 图像行跨度按 ROS 消息的 `step` 处理（兼容行尾填充），RGB/BGR 都支持，并做尺寸与溢出检查。
- **结果**：匹配上的姿态反馈与图像时间偏差稳定在 **约 5–12 ms**，消除了「图像还没到、姿态已经转了」造成的系统性偏差。

### 2. 装甲板检测

- HSV 颜色阈值提取蓝色灯条，形态学去噪后取外部轮廓。
- 灯条筛选：面积、长宽比、长边倾斜角、尺寸上限四道硬筛；长边方向做了 y 分量归一，保证角度定义一致。
- 灯条配对：先按**角度差、长度差、中心高度差、间距比**做硬筛，再对这四项做归一化加权评分（角度 0.30 / 长度 0.25 / 高度 0.25 / 间距 0.20），得到 0–100 的置信度；按评分从高到低贪心配对，配合去重避免同一灯条被重复使用。
- 输出角点统一为左上、右上、右下、左下顺序，置信度直接作为后续跟踪的质量门槛。
- 配对过程全程可视化（轮廓、配对线、角点框、置信度数字），便于定位漏检/误配。

### 3. 位姿解算（PnP）

- 平面目标用 `SOLVEPNP_IPPE`，四个角点即可解出位姿。
- 解出后用 `projectPoints` 算**像素 RMSE 重投影误差**作为可信度，坐标链严格走 `相机光学系 → 云台系 → IMU 稳定系`（旋转矩阵 + 平移 + 姿态四元数）。

### 4. 卡尔曼跟踪与预测（本项目核心）

状态为 `[位置(3), 速度(3)]`，匀速模型，协方差 6×6。相比单帧 PnP，这一层解决三件事：

- **速度估计**：用连续观测估计目标速度，供第五讲算提前量。
- **丢检续跟**：本帧没观测到也照样按 `F` 预测，云台不会因单帧漏检而停摆。
- **抑制野值**：单帧跳变 / 跳板不会把状态带偏。

关键设计与实测依据：

| 设计 | 做法 | 依据 |
| --- | --- | --- |
| 过程噪声离散化 | 连续白噪声加速度模型 → `Q` 的 dt、dt²/2、dt³/3 分块 | 让协方差随 `dt` 物理地增长 |
| 数值稳定 | 协方差更新用 **Joseph 形式** | 长跑后仍保持对称正定 |
| 新息门控 | `d² = νᵀS⁻¹ν` 对照 3 自由度 χ²（99% 置信 → 11.34），超限本帧不更新 | 门限只在阈值上做 0/1 判决，不改变状态含义 |
| 门控失效策略 | 超限时**保留预测**、让 `P` 继续增长，下次门限自然放宽 | 状态越不确定，判据就该越宽松 |
| 重建 vs 硬撑 | 连续 `missed_frames` 达 5 帧才重新初始化 | 区分「单帧野值」与「真跟丢」 |
| 选板 | 已跟踪时选离**预测位置**最近的；未跟踪时选重投影误差最小的 | 前后帧盯同一块板；初始选最可信的板 |
| 开火可解释性 | 输出 `frames_since_update`，纯预测帧 > 0 | 下游据此禁止在盲推状态下开火 |

参数也不是拍脑袋：`q = 4 m/s²` 对应仿真平移靶峰值加速度约 1.23 m/s²（考虑急停裕量）；`R = 0.03 m` 是按「PnP 静止靶逐轴误差约 1–2 mm，但工程上 R 同时兼任平滑度旋钮」的思路设置。按该组参数推算稳态增益 ≈ alpha–beta(α≈0.40, β≈0.10)，即滤波器自己收敛出的平滑度与「稳速度」倾向，无需手调。

### 5. 弹道解算与开火（进行中）

- 抛体运动解析解：给定初速 `v0`、水平距离 `d`、高度差 `h`，解出仰角 θ 与飞行时间，取低伸弹道根；判别式小于 0 时返回无解而不发危险指令。
- 云台指令统一到 IMU 系绝对角，IO 层再负责角度单位与方向、以及 `allow_fire` 安全门。

### 6. 量化验收工具（可复现的证据）

为了不靠「看着差不多」，我基于仿真器发布的车体真值话题 `/lesson/armor_truth`（`LessonTruth` / `LessonArmorObservation` 消息类型为本项目新增）写了一套验收演示：

- **静止靶**：同一帧上同时画 绿框（真值）、黄框（PnP 位姿投影）、品红框（t+250 ms 预测位置）、橙框（t+250 ms 的真值），左下角实时显示 PnP 与真值的距离误差 `|d|`、逐轴差、重投影误差。
- **平移靶**：在真实观测到目标的那一帧预测 t+250 ms 位置，等真值时间戳到达 t+250 ms 时结算误差，统计**均值 / 最大值 / 结算次数**。
- 结算规则刻意做了防作弊：真值快照取离 t+n 最近的采样（真值约 19 Hz，避免半个周期约 25 ms 的系统偏差）；掉帧超过 90 ms 丢弃；同 id 真值距离预测超过 1 m 视为配错目标不计分。
- 运行 `configs/lesson04_static.yaml`、`configs/lesson04_prediction.yaml` 即可复现，画面可按真实帧率录成 MP4。

> 说明：仿真器的场景、渲染与 ROS2 桥接是队伍培训框架提供的；`lesson_truth.rs` 真值话题、`LessonTruth` / `LessonArmorObservation` 消息、演示循环、画框/HUD 工具、检测/跟踪/弹道算法均为我实现。

## 已知工程细节与踩过的坑

- **装甲板尺寸修正**：第三讲输出的是两根灯条外接矩形的四角，不是整块板外框。按常见的 135×125 mm 板解 PnP 会把高度估计放大两倍多、距离稳定偏近约 10 cm；我据仿真实测改为约 140×59 mm（小板）/ 238.6×59 mm（大板），PnP 距离误差下降一个量级。
- **坐标系互逆**：演示里比较 PnP 与真值在相机系进行，预测在 IMU 系外推；结算时由真值经 `R_camera2gimbal` 与 `imu_q` 旋回 IMU 系比较，换算链与 `solveArmorPose` 严格互逆，才能保证对比公平。
- **选板不按重投影误差**：远处小板的平面 PnP 重投影误差可能反而更小，只看重投影误差会把目标锁到别的车身上；锁定阶段改为取「离预测最近」并记住真值数组下标（帧间稳定）。
- **门限与重建**：门限过严会让真实目标被拒，过松会放进跳板；因此引入「连续丢失 5 帧才重建」，既避免单帧误判重置、又能在真跟丢时及时重新起步。

## 环境

- Ubuntu 22.04、ROS2 Humble、CMake + C++17
- OpenCV、Eigen3、yaml-cpp
- Rust 1.95.0（编译仿真器）

## 构建与运行

```bash
# 主程序（含 ROS2 消息）
./scripts/build_training.sh

# 仿真器（首次较慢）
./scripts/build_simulator.sh
```

两个终端都在仓库根目录：

```bash
# 终端 1：仿真器；场景内 F7 开始计时
./scripts/run_simulator.sh

# 终端 2：验收演示（静止靶 → 平移靶）
./scripts/run_training.sh configs/lesson04_static.yaml
./scripts/run_training.sh configs/lesson04_prediction.yaml
```

`q` / `Esc` 结束并写出 MP4。相机内参、坐标变换与 `prediction_ms` 等见 `configs/`。
